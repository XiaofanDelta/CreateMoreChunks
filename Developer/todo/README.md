# CMC 待办导航

> `Developer/todo/` 下四个文件的分工. 先看这张表, 再决定把事项写到哪里.

| 文件 | 装什么 | 什么时候看 |
|---|---|---|
| [Main.md](./Main.md) | 眼下能动手的: 待设计 (工程侧) / 待实现 / 历史遗留 / 打磨 | 每次开发前 |
| [Setting.md](./Setting.md) | 设定与设计待定项: 章节 / 橡胶 / 星球 / 源质 / 彩蛋 | 写文档、定方案时 |
| [Plan.md](./Plan.md) | 长远计划与未成熟的想法 | 规划版本时 |
| [Done.md](./Done.md) | 完成记录, 按版本归档 | 发布时 |

---

## 怎么用

1. **新事项先判断性质**
   - 能直接动手改代码 → `Main.md`
   - 得先定设定 / 玩法 → `Setting.md`
   - 大块头、暂不排期、只是想法 → `Plan.md`
2. **同一事项只写一处**. 跨文件用相对链接引用, 不要复制整段.
3. **完成后**在原文件勾掉, 并按版本同步到 `Done.md`.
4. **设定定稿后**落到 `Developer/docs/` 的对应文档, 在 `Setting.md` 勾掉, 保留一句结论.
5. 这里只记"要做什么", 不记"怎么实现"的细节——实现细节进 `docs/` 或代码注释.
