# CMC 文档索引

> `Developer/docs/` 下的设计文档, 按文件名 A-Z 排列.
> 
> 本目录只放**设计参考**, 不是运行时文件——改文档不会影响游戏, 改代码才会.
> 
> 模组清单不在本目录: 见 [`../ModsList.csv`](../ModsList.csv) (PCL2 CE 导出, 由 `tools/CheckModsList.py` 校验).
> 
> 新人建议阅读顺序: Worldview → Gameflow → 其余按需.

---

## 一、文档清单

### [Gameflow.md](./Gameflow.md)

0~4 章的完整流程、关键配方、进度节点速查.

- **事实源**: 配方与章节流程以本篇为准
- 什么时候改: 增减章节、关键配方变化、进度节点增删、`Gameflow` 与代码不一致时

### [InfinitySource.md](./InfinitySource.md)

11 种无限源质的配方、代表物、痛点与设计说明.

- **事实源**: 无限源质以本篇为准 (Worldview / Gameflow 只做概述并链接到这里)
- 什么时候改: 源质种类、代表物、用途、"无限"的实现方式变化

### [Planet.md](./Planet.md)

9 种星球 (含太阳) 的获取方式、当前实现状态、海王星的 3×1×3 水坑判定.

- **事实源**: 星球清单与获取方式以本篇为准
- 什么时候改: 星球配方变动、海王星定稿、新增星球

### [QuestsStyle.md](./QuestsStyle.md)

任务书文风指南: 先问题后答案、短、留白、叙事化、颜色代码语义、自查清单.

- **事实源**: 文案风格以本篇为准
- 什么时候改: 叙事风格调整、新增颜色语义

### [Worldview.md](./Worldview.md)

世界观与设定: 世界为什么只剩一个区块、NULL 与错误区块、湮灭与创造、章节节奏.

- **事实源**: 设定只写在这里, **不写具体配方**
- 什么时候改: 核心设定变化、章节定位调整

## 二、一句话记住分工

| 想知道 | 看 |
|---|---|
| 某个东西怎么做、在第几章 | **Gameflow** |
| 某个源质用什么换、为什么这么设计 | **InfinitySource** |
| 某个星球怎么拿、现在做到哪了 | **Planet** |
| 任务书该怎么写 | **QuestsStyle** |
| 这个世界为什么是这样 | **Worldview** |

## 三、编辑约定

1. **同一事实只写一处**: 流程 → Gameflow, 源质 → InfinitySource, 设定 → Worldview, 文案 → QuestsStyle.
   其他文档要做的是**概述 + 链接**, 不是复制整张表.
2. 文档之间用相对链接; 引用代码时写清 `文件:行号`, 方便回查.
3. 提到物品 / 配方 id 必须与代码一致, 统一 `cmc:` 命名空间.
4. 改动章节结构或配方数字后, 同步 Gameflow 的"关键合成链速查"和"进度节点速查"两张表.
5. 新增文档要在本索引登记, 并写清"事实源"和"什么时候改".
6. 文档里的 `待定` 属于设计占位, 不是待办; 要追踪的事写进 [`../todo/`](../todo/), 按 [`../todo/README.md`](../todo/README.md) 的规则归位.
